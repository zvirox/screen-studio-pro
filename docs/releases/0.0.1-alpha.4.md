# Release notes — v0.0.1-alpha.4

**App version:** `0.0.1+alpha.4` (semver-equivalent to the tag `v0.0.1-alpha.4`; Tauri bundlers reject `-` in version strings).  
**Status:** Strict Alpha Track — prerelease build.

This hotfix repairs the Flatpak startup crash reported in `v0.0.1-alpha.3`. The application code and DESIGN.md v3.1 studio interface are otherwise unchanged.

---

## Fixed

- **Flatpak now bundles its tray runtime.** Tauri loads `libappindicator3.so.1` dynamically during startup. The alpha.3 Flatpak omitted that library and its libdbusmenu/libindicator dependencies, causing a Rust panic before the main window could open.
- The Flatpak manifest now builds the pinned Flathub shared-module recipes for libappindicator, libdbusmenu, libindicator, dbus-glib and intltool inside `/app`.
- The release workflow checks the built sandbox for all required tray libraries and unresolved transitive dependencies.
- An Xvfb + D-Bus startup smoke test must keep the application alive for 20 seconds without a loader panic before the `.flatpak` bundle can be created and uploaded.

## Reproduction evidence

On the installed alpha.3 bundle, `flatpak run com.zvirox.screenstudiopro` exited with status `134` and:

```text
Failed to load ayatana-appindicator3 or appindicator3 dynamic library
libayatana-appindicator3.so.1: cannot open shared object file: No such file or directory
libappindicator3.so.1: cannot open shared object file: No such file or directory
```

## Upgrade

Download `ScreenStudio-Pro-v0.0.1-alpha.4-x86_64.flatpak`, then install it over the previous version:

```bash
flatpak install --user ./ScreenStudio-Pro-v0.0.1-alpha.4-x86_64.flatpak
flatpak run com.zvirox.screenstudiopro
```

If alpha.3 was installed system-wide, use `sudo flatpak install ./ScreenStudio-Pro-v0.0.1-alpha.4-x86_64.flatpak` instead, or remove the system installation before installing for the current user.

## Capability and validation boundaries

- This is a packaging-only hotfix; no recording, capture, encoder or UI behavior changed.
- The alpha.3 capability matrix still applies: x264 is the working encoder, VAAPI/NVENC remain unimplemented, and hardware performance is not claimed.
- Package startup must pass the new Flatpak release smoke gate. Full recording validation and installation on clean test VMs remain open.
- README previews remain mocked-IPC frontend renders, not packaged-app recording sessions.

See the [README installation guide](https://github.com/zvirox/screen-studio-pro/blob/v0.0.1-alpha.4/README.md#-installation) for the other package formats and exact commands.
