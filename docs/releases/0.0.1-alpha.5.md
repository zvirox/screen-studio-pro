# Release notes — v0.0.1-alpha.5

**App version:** `0.0.1+alpha.5` (semver-equivalent to the tag `v0.0.1-alpha.5`; Tauri bundlers reject `-` in version strings).
**Status:** Strict Alpha Track — prerelease build.

This packaging-only hotfix moves the Flatpak from GNOME 48 to GNOME 49 to address the remaining alpha.4 startup crash. The application code and DESIGN.md v3.1 studio interface are otherwise unchanged.

---

## Changed

- **The Flatpak now uses the GNOME 49 runtime and SDK.** Alpha.4 resolved the appindicator loader panic, but its GNOME 48 WebKit stack could still receive an external `SIGKILL` (status `137`) during startup.
- The bundled libappindicator, libdbusmenu and libindicator tray runtime remains in place.
- Release CI still checks every required tray library and its transitive dependencies, then requires the built application to remain alive for the full 20-second Xvfb + D-Bus startup gate before creating and uploading the `.flatpak` bundle.
- No WebKit sandbox, compositing or software-rendering environment override is shipped; those experiments were not reliably sufficient.

## Diagnostic evidence

The same alpha.4 binary and real application data were tested against both installed runtimes:

- GNOME 49: five of five eight-second launches and three of three full 20-second launches survived.
- GNOME 48: three matched control launches exited with status `137` within five seconds.
- GNOME 48 supplied WebKitGTK 2.50.6 and Mesa 25.3.3; GNOME 49 supplied WebKitGTK 2.54.1 and Mesa 26.2.2. This runtime-level A/B result does not identify which individual component corrected the failure.

These diagnostics establish the runtime change being shipped; they are not a substitute for testing the published alpha.5 bundle.

## Upgrade

Download `ScreenStudio-Pro-v0.0.1-alpha.5-x86_64.flatpak`, then install it over the previous version:

```bash
flatpak install --user ./ScreenStudio-Pro-v0.0.1-alpha.5-x86_64.flatpak
flatpak run com.zvirox.screenstudiopro
```

If alpha.4 was installed system-wide, use `sudo flatpak install ./ScreenStudio-Pro-v0.0.1-alpha.5-x86_64.flatpak` instead, or remove the system installation before installing for the current user. Flatpak installs the required GNOME 49 runtime from the configured remote when needed.

## Verification boundary

The published bundle must pass both release jobs, including the library and 20-second startup gates, and then survive repeated 20-second launches from the existing system Flatpak installation before this startup correction is considered verified. Final release and installed-system evidence will be recorded after publication.

## Capability and validation boundaries

- This is a packaging-only hotfix; no recording, capture, encoder or production UI behavior changed.
- The alpha.3 capability matrix still applies: x264 is the working encoder, VAAPI/NVENC remain unimplemented, and hardware performance is not claimed.
- Startup checks are not recording-session validation. Full recording validation and installation on clean test VMs remain open.
- README previews remain mocked-IPC frontend renders, not packaged-app recording sessions.

See the [README installation guide](https://github.com/zvirox/screen-studio-pro/blob/v0.0.1-alpha.5/README.md#-installation) for the other package formats and exact commands.
