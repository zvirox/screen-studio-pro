# Release notes — v0.0.1-alpha.3

**App version:** `0.0.1+alpha.3` (semver-equivalent to the tag `v0.0.1-alpha.3`; Tauri bundlers reject `-` in version strings).  
**Status:** Strict Alpha Track — prerelease build.

This release delivers the **DESIGN.md v3.1 “Legible, Responsive Studio”** refinement. It preserves the Burgundy/Obsidian identity and wide desktop tri-panel architecture while improving compact layouts, accessibility and documentation.

---

## Highlights

1. **Responsive Record workspace**
   - Canonical three-panel studio at desktop widths.
   - Two-column inspector + preview/mixer layout from 720–1119px, with the expanded gallery spanning both columns.
   - Stacked panels below 720px in DOM reading order, without horizontal page overflow.

2. **Clearer controls in both themes**
   - Refined glass separation, text contrast, control sizing, focus states and shared button treatment.
   - Improved navigation, mixer, gallery, settings and recording-HUD states.
   - Motion keeps controls legible and respects reduced-motion preferences.

3. **More reliable region selection**
   - Crop dragging is registered with the active drag provider.
   - Pointer movement is converted into native-source coordinates.
   - Letterboxed source geometry is respected; keyboard nudges remain native-pixel steps.

4. **Keyboard-accessible Settings**
   - Arrow-key navigation across settings tabs.
   - Explicit tab/panel relationships and corrected focus behavior.
   - 36px navigation targets and reachable controls throughout the polished surfaces.

5. **Documentation and previews**
   - Expanded installation, FAQ and troubleshooting guidance grounded in validated behavior.
   - Four regenerated 1440×960 previews: Record dark, Record light, Settings and Library.
   - Every preview is explicitly labelled as a Vite frontend render with mocked Tauri IPC; the Library preview uses sample rows.

## Verification

- `npm run typecheck` — passed, 0 errors.
- `npm run lint` — passed, 0 errors and 0 warnings.
- `npm test` — **321 tests passed across 35 files**.
- `npm run build` — production frontend build passed.
- Browser checks — 1440×960, 1040×680 and 640×800; dark and light themes; keyboard navigation; reduced motion; no horizontal overflow or console errors.
- Commit `2fd2b80` — CI run [`44995837385`](https://github.com/zvirox/screen-studio-pro/actions/runs/44995837385) passed both frontend and Rust jobs.
- Local Rust rerun — blocked while `ffmpeg-sys-next` generated bindings against the host’s FFmpeg 8 headers because CUDA SDK types were unavailable. No Rust source changed in this release; Ubuntu CI supplies the supported build environment.

## Known limitations

- Release packages are built and attached by CI but **have not been install-verified on test VMs**.
- Hardware-encoding performance is not claimed: VAAPI/NVENC backends remain stubs and x264 is the working fallback.
- The README images are **mocked-IPC UI previews**, not real recording sessions or packaged-app captures. Real in-app screenshots remain open.
- AUR packaging/announcement, the fresh-profile ≤60s first-recording metric and the remaining compositor-specific validation gates are still open.
