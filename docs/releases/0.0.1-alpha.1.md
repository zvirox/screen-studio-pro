# Release notes — v0.0.1-alpha.1

**App version:** `0.0.1+alpha.1` (semver-equivalent to the tag; Tauri bundlers reject `-` in version strings). **Status:** alpha — packages are being built from this tag. These notes are written from the evidence ledger in `PLAN.md` and the compositor observations in `docs/portal-support.md` — they distinguish implemented, automated-verified and live-verified features, and do not claim unmeasured targets.

## Scope

A Wayland-first screen recorder with audio, a floating recording HUD, a local recording library and a glass UI. Streaming, scenes, replay buffer and a plugin API are explicitly **not** in this release (PRD non-goals N1/N2 and V2/Later tables).

## Known quirks

1. **Portal negotiation is compositor-specific.** KWin advertises variable framerate (0/1) with a separate max frame rate; a `[60..60]` range kills the stream. DMABUF modifier `0` means invalid modifier, which yields zero frames if accepted. The app therefore omits the modifier property and includes 0 in the range. Details and repro steps in `docs/portal-support.md`.
2. **Node sizes are session-local.** The same monitor has appeared as 1920×1080 and 1919×1079; sizes are taken from the portal response, never hand-pinned.
3. **cpal/ALSA virtual inputs on the test host delivered no samples** even though native PipeWire capture saw the injected tone; the live A/B rig fed the mic ring from a real PipeWire capture instead. This is a rig/platform observation, not a claim about hardware microphones.
4. **Load sensitivity of the x264 fallback.** Under external CPU contention, drop rates spiked far above calm-run values; PRD's 0.5% drop row applies to the hardware path that is not yet implemented.
5. **Rare unexplained shutdown/link anomalies** (see tray row and webcam row above) are documented but unreproduced under controlled replay.
6. **No published installer.** The release workflow and Flatpak manifest are untested against a real tag; AUR packaging is follow-up work.
