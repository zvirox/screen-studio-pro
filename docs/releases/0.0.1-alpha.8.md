# Release notes — v0.0.1-alpha.8

**App version:** `0.0.1+alpha.8` (semver-equivalent to the tag `v0.0.1-alpha.8`; Tauri bundlers reject `-` in version strings).
**Status:** Strict Alpha Track — prerelease build.

This release fixes the Flatpak offline bundle launch failure where the WebKitGTK webview failed with `Could not connect to localhost: Connection refused`.

---

## Fixed

- **Enable `custom-protocol` for offline Flatpak builds.** When compiling with raw `cargo build --release` (used inside the Flatpak build sandbox), Tauri v2 previously defaulted to development mode without custom protocol support, causing the webview to attempt to connect to `http://localhost:1420` instead of serving the bundled static frontend assets. Declared `custom-protocol = ["tauri/custom-protocol"]` in `src-tauri/Cargo.toml` and enabled `--features custom-protocol` in the Flatpak build manifest.
- **Added release pipeline assertions.** The Flatpak CI verification step now validates that the built binary contains `tauri://localhost` and asserts that startup logs do not contain connection refused or localhost connection errors.

## Verification

- Built release check with `--features custom-protocol` verified offline frontend asset embedding.
- Verified that binary contains `tauri://localhost` custom protocol scheme and static assets.
- Frontend test suite (35 files, 321 tests), lint, and typecheck all passing.
- Backend test suite passing.

## Validation boundaries

- Packaging-only changes: core recording, PipeWire capture, encoder, and UI component behavior are otherwise unchanged from alpha.7.
